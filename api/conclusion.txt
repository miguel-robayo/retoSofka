CONCLUSIONS

  The REST signup and login services of https://www.demoblaze.com/ were successfully automated, identifying the inputs
  and capturing the outputs of the following cases:

    - Create a new user in signup                     -> ""
    - Try to create an existing user                  -> {"errorMessage":"This user already exist."}
    - Valid username and password in login            -> "Auth_token: <token>"
    - Invalid username and password in login          -> {"errorMessage":"Wrong password."}
    - Non-existent user in login                      -> {"errorMessage":"User does not exist."}

  Inputs: POST with JSON body { "username": "<user>", "password": "<password in Base64>" }

  During execution, the following findings were identified:

    - All services return HTTP 200 even in error cases; errors are only identified by the errorMessage field in the
    body, so validation cannot rely on the status code alone
    - A successful signup returns the plain text "" (with a line break) instead of JSON, which makes validation harder
    - The password is sent Base64 encoded (not encrypted), so it is easily reversible
    - The login token is the username plus data encoded in Base64, not a secure token (e.g. JWT)

  Technical level findings:

    - Incorrect folder structure (files outside src/test/java), Maven could not find the runner
    - Unique username generated per execution (callonce) so the creation scenario is repeatable

  Benefits of using the Karate Framework

    - Ease of creating and executing test scenarios
    - no need for additional libraries such as RestAssured
    - Simple JSON validation using match
    - Use of Background for baseUrl and test data
    - HTML report with the request and response of each scenario
    - Clear separation between runner and feature files

  Improvement opportunities

    - Implementation JSON schema validation
    - Externalize test data and environments (karate-config.js)
    - Additional negative validations (empty fields, invalid body)
    - Integrate with CI/CD pipelines
